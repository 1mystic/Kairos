# 16 · Ask AI

After a student has answered (or revealed the solution) they can send the question to an AI assistant and save the explanation they like.

## where it shows
Only where the answer is already visible: practice feedback (after Check, or after Reveal on self-check questions), the practice summary and mistake review, and mock review after submission. **Never** in the live mock runner (`cbt/ExamFlow.tsx`) and never before a practice question is answered. Call sites mount `AiHelp` (`components/AiNotePanel.tsx`) next to a `QuestionView` that has `showSolution`.

## how it works
- `lib/askAi.ts` (pure): `buildAiPrompt` (exam, subject/chapter, stem, options, type + answer format; if revealed also the key, official solution and the student's answer; then instructions), `aiTarget` / `aiTargetUrl` (ChatGPT, Claude, Perplexity, Google AI Mode prefill via `?q=`; Gemini has no prefill so it opens `/app` and the prompt goes via clipboard). URLs over ~7000 chars get a shortened prompt; the full one is on the clipboard.
- `AskAiButton`: split button, drawn as one fused pill (`components/AskAi.css`: main part + a deeper-tint chevron part, no borders). The call sites pass the real exam id (practice runner and summary: the session's exam; mock review: the paper blueprint's exam) so the prompt names the exam. Main part opens the last-used provider (localStorage `kairos.askAi.provider`, default ChatGPT); the chevron lists all. A click copies the full prompt and opens the site in a new tab (`noopener,noreferrer`).
- `AiNotePanel`: paste, edit, delete the student's saved explanation, rendered with the same safe markdown + KaTeX renderer as solutions (`trust:false`, no raw HTML). Labelled as AI-generated and not checked by Kairos. Rendering goes through `NoteContent` (`components/NoteContent.tsx`): markdown + KaTeX, plus Mermaid diagrams (below).

## mermaid diagrams
A fenced ```mermaid block in a note renders as a diagram. `mdBlocks.ts` now tags every fenced block that has a language with `data-lang` (`<pre class="kc-code" data-lang="mermaid">`; the value is limited to `[a-z0-9_+#-]{1,20}`, the body stays HTML-escaped). `NoteContent` finds the `mermaid` blocks in the rendered DOM and replaces each with the SVG from `mermaid.render()`. The `mermaid` package (12.x) is a lazy chunk: `import('mermaid')` runs only when a note contains a mermaid fence, with `{ startOnLoad: false, securityLevel: 'strict', theme }` (dark or default from `data-theme`, redrawn when the theme changes). `strict` mode sanitises the SVG and disables click handlers; that SVG is the only HTML injected, everything else stays escaped. On a parse error the code block stays and a short "Diagram could not be drawn" line appears above it. The chunks are not precached (precache is the app shell only, `vite.config.ts` `globPatterns`); they are cached at runtime on first use by the `kairos-chunks` rule.

## saved answers page (`/saved`)
`app/src/saved/` (`savedRoutes`, lazy group `lazySavedRoutes`; sidebar entry "Saved" after Practice). Lists every note newest first (`UserStore.listAiNotes`, same for guests and signed-in users). Each card: exam chip, chapter name (taxonomy), the stem snippet (or `Question <qid>`), provider and date, and a three-line preview. "Show answer" expands the full rendered note plus the original question with its official solution, loaded from the bank shard (`getShard(version, exam, subject, chapter)`, subject from the taxonomy); notes without `exam`/`chapter` show only the note. Filters: search (stem, note text, chapter, exam, provider, qid), exam, newest/oldest. Actions: Edit (the `AiNotePanel` editor), Delete (confirm, one write), "Practise this chapter" (`/practice/<exam>/<chapter>`). Empty state explains how to save with Ask AI.

## privacy
Nothing is sent automatically. The question text leaves the app only when the student clicks a provider, and goes to that third-party site via the URL / their clipboard. Kairos never calls an AI API and has no keys.

## data
`users/{uid}/ai_notes/{qid}`: `{ qid, text (<= AI_NOTE_MAX = 20000 UTF-16 units, clipped without splitting a surrogate pair), provider, updatedAt, savedAt?, exam?, chapter?, stem? }`. The optional question reference says where to find the question again (the bank is static shards by exam/subject/chapter): `exam` (1..20), `chapter` (taxonomy chapter id, 1..40), `stem` (plain-text snippet, 0..300, images and markdown marks dropped). `AiHelp` computes it from the question (`aiRefOf`) and passes it as `putAiNote(qid, note, ref?)`; an edit that does not know the question keeps the stored reference. Older notes have none and still list fine. `updatedAt` is the server time; `savedAt` (int ms epoch, client time of the student's last save, > 0 and at most server time + 10 min) is optional, written on every save and copied unchanged when guest notes migrate, so the displayed date survives sign-in. The app shows `savedAt ?? updatedAt`. Owner-only read/write in `firestore.rules`. Guests keep it in IndexedDB via `LocalStore` and it migrates on sign-in. One write per save/delete, through `UserStore` (`getAiNote`, `putAiNote`, `deleteAiNote`, `listAiNotes`). `listAiNotes` is one list read (capped at 2000 on Firestore), sorted newest first by the displayed save time.

## export and migration
Settings > Download your data includes `ai_notes` (`UserStore.listAiNotes`, including the reference fields). The migration dialog lists `N saved AI explanations` next to the other counts (`MigrationPlan.counts.aiNotes`).
